换算采用短上下文美元/百万 token：输入倍率 = 输入单价/2，输出倍率 = 输出单价/输入单价，缓存读倍率 = 缓存读单价/输入单价。不预乘长上下文系数，不配置 `_long`、`_default`。

CacheWriteRatio 没有 options/管理接口入口。上述快照只有在基础模型实际回退值为 `1.25` 时才能复现缓存写单价；本地测试使用 `1.25`，目标实例仍需核对。不能把不存在的管理字段加入 JSON 并假设已生效。Chat 还需清点基础或档位 `PerCallPricing`，因为有效固定价仍优先于 token 倍率；Responses 忽略固定价。

## 发布前需要补齐的现场资料

1. 确定目标实例、部署方式、当前发布版本、需支持的模型/渠道和实际返回的档位；重新读取官方文档并确认运营定价。
2. 只读备份 `ModelRatio`、`CompletionRatio`、`CacheRatio`、`PerCallPricing` 的原始 options JSON，保存键是否存在。管理价格列表会计算默认值，不能用展示值代替原始配置备份。备份仅含价格项，不导出密钥或全部 options。
3. 清点已有档位后缀键、真实模型名冲突、映射规则、精确长上下文阈值及缓存写回退。Chat 基础模型为映射后模型；Responses 为 `original_model`。
4. 填入上表“当前值”，标记每项为新增/替换/无变化；保留不属于本次的配置。核对每个实例实际 `SYNC_FREQUENCY`，代码默认 600 秒不能替代现场值。
5. 审查全量测试遗留失败和环境限制；选择可监听本地端口、可访问测试依赖的环境补跑。获得配置写入、外部付费验证及发布授权后再执行对应操作。

## 发布及验收顺序

- 备份配置与上一发布版本，先在隔离环境验证；同名模型配置是全局范围，不把价格配置当成渠道级灰度开关。
- 部署代码本身就会启用 GPT-6+ 长上下文规则，已有档位价格键也会开始参与结算，未新增配置不代表无计费变化。
- 使用审查后的增量请求体更新配置；核对 API 的 `success`，再逐实例读取并实际验证，不能仅等待 600 秒就宣布全部生效。
- 对实际支持的档位验证 Chat/Completions/Responses 的普通及 SSE，请求和响应档位不同、default/缺失回退、模型映射、部分配置与缓存读写。记录脱敏 request ID、实际 usage、基础模型、响应档位、价格参数、quota 与余额变化。
- 关注预估与实际扣费差异、异步扣费错误和日志差异。预估、预扣仍用旧口径，不承诺高价档位费用被预估上限覆盖。旧 Completions SSE 使用本地 token 估算；异常缓存统计处理是存量限制。
