# 手动模型测试联动动态优先级

## 背景与目标

渠道列表的 View Models 已通过现有测试接口提交指定模型。测试完成后，立即以该次结果和最近窗口数据计算该渠道、该模型的动态优先级，避免等待定时任务。

## 方案设计

- 测试执行层返回实际调用的观测数据，统一处理普通聊天和 Responses 路径，消费日志不重复写入测试评分样本。
- 指定模型且动态评分开启时，同步记录成功或失败样本；读取同模型候选数据，复用现有评分算法，只更新目标渠道该模型的所有分组行。
- 接口返回动态优先级及更新状态，并在现有消息中显示结果，现有前端可直接展示。
- 保留 POST 模型参数，兼容 GET 查询参数；模型名称必须精确匹配。
- 旧版 Air 前端仅在选定模型时传递查询参数，避免默认测试发送字符串 `undefined`。

## 影响范围

不新增 API、数据库字段或分发规则。不自动启用禁用渠道或模型，不修改其他渠道的评分。Redis 或评分失败不改变测试本身的成功状态。

## 验证方式

通过内存 SQLite、模拟 Redis 和本地模拟上游验证：指定模型、模型映射、普通聊天与 Responses 各记一次、失败更新、分组同步、其他模型隔离、动态评分开关及 Redis 失败降级。运行相关 Go 测试、全项目构建与静态检查。

## 验证结果

- 新增测试及渠道重试、测试请求兼容性测试连续运行 10 次通过。
- 新增测试通过竞态检测；评分窗口、评分算法、模型包测试通过。
- `go build ./...` 与 `go vet ./...` 通过。
- controller 包中已有的两项用量禁用测试和视频放大生命周期测试失败；使用修改前源码的 Go overlay 复现相同失败，与本次改动无关。
