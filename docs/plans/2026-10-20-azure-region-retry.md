# Azure 渠道区域与重试限制

## 背景与目标

在渠道详情中展示并允许修改 Azure 的 `config.region`。Azure 请求失败后仅使用初始渠道同区域的 Azure 渠道重试，候选耗尽后返回已有错误。

## 方案设计

- 复用后端已有的 `ChannelConfig.Region`，无需新增数据库字段或 API。
- 在实际前端仓库 `ezlinkai-web/sections/channel/channel-form.tsx` 的 Azure 配置区增加区域输入，沿用现有配置回填和保存逻辑。
- 在 `controller/retry_policy.go` 中固定请求初始 Azure 区域，使用已有能力过滤选渠方法覆盖静态、动态优先级；区域比较忽略大小写及首尾空格。
- 在 `controller/relay.go` 的各重试入口传递该限制，Azure 候选耗尽时不清空失败列表、不回退最后一个渠道。未配置区域时停止跨渠道重试，其他类型保留原逻辑。
- 增加重试回归测试，覆盖区域过滤、优先级降级、耗尽与非 Azure 兼容性。

## 影响范围

后端重试策略及关联前端渠道表单。不需要数据迁移。已有 Azure 渠道需填写区域才能跨渠道重试。

## 验证方式

运行 Go 重试回归测试、相关包测试、全量构建与静态分析，以及前端类型和格式检查。

## 验证结果

- 新增重试测试通过，覆盖静态/动态优先级、区域大小写与空格、类型与分组模型过滤、禁用渠道、无区域、候选耗尽及非 Azure 循环重试。
- `go build ./...`、`go vet ./...`、前端 `tsc --noEmit --incremental false` 和表单 Prettier 检查通过。
- 全量 Go 测试存在原有失败：图片解码、近期使用量禁用、Flux 视频生命周期、Anthropic beta 过滤和 Kling 模型解析。使用 Go overlay 恢复原始生产代码后，四个包中的失败保持一致；另一个 `model` 包使用量窗口测试受运行时刻影响，向下取整后的时间可能早于测试设置的窗口，对照运行时已跨越该边界而通过。
- 前端表单 lint 的 6 个错误及 36 个警告与修改前完全一致，本次未增加 lint 问题。
