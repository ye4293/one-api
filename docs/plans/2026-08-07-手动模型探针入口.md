# 手动模型探针入口（渠道列表 View Models 下方）

## 背景与目标

探针功能（`controller/channel_upstream_probe.go`）已上线，但**只被定时巡检任务调用**。管理员想在渠道列表页 Actions 菜单（View Models 下方）**手动触发**探针，即时诊断上游模型差异，并可在弹框内直接勾选应用增删。

四个现有 HTTP handler（detect/apply/detect_all/apply_all）全部 `allowAutoApply=false`，刻意不走探针 —— 保留管理员最终决定权。手动探针延续这一原则：**探针只出诊断结论，管理员勾选后才应用**，应用复用现有 apply 接口。

### 已确认的决策
1. **只探上游 diff**（pendingAdd ∪ pendingRemove），models 参数必填，不探渠道全部 models
2. **弹框内可直接勾选应用**探针结论
3. **不受全局开关 `UpstreamModelProbeEnabled` 与渠道级 `UpstreamModelProbeDisabled` 控制** —— 手动 = 显式管理员意图
4. **已启用 Redis** → 用现成的 `common/redis.go` 原语做渠道级软租约锁
5. **不需要续跑**，关弹框就重来 → 探测结果只在前端 state，后端不存 session
6. **写 logs 表**，带 `probe_source:manual` 标记

## 关键约束（实现时必须遵守）

**E（最危险）** — `probeUnsupportedReason:422` 第一个判断是渠道级 `isUnsupportedTestChannel(channel.Type)`。若渠道类型不支持（Midjourney/Keling/Flux/Replicate 等 8 种），循环里每个模型都在 `budget.take()` **之前** `continue`（`:661`），不消耗预算、无停止机制，全判 `skipped`，而 `probeVerdictApproves(skipped,*)=true` → **UI 把全部模型标成「建议添加」，一次请求都没发**。必须在 handler 入口做渠道级短路，`{supported:false}` 直接返回。

**A 预算耦合** — `probeBudget.take()` 扣减包级 `upstreamProbeRoundBudget`，只在定时任务每轮 `resetProbeRoundBudget()` 重置。手动探针不得触碰它，否则会抽干定时任务额度、导致本轮剩余渠道自动同步/删除静默失效。

**B 统计污染** — `probeChannelModels` 内 `probeStat*.Add()`（6 个包级 atomic）是定时任务轮末统计用，手动探针不得累加。

**G 成本/注入防线** — `req.Models` 必须与 settings 里 pendingAdd∪pendingRemove **求交**，交集外的原样落 `rejected` 不探。否则接口成了「以管理员身份向任意上游发任意模型名付费请求」的放大器。外加 per-request 硬上限。

**I 定时任务避让** — 定时任务检测到该渠道有活跃手动探测标记时，必须把 `allowAutoApply` 整个置 `false`（不是只跳过探针，否则会不经探针直接自动应用，更糟）。

**settings 只读** — 手动探针 handler 绝不调 `saveChannelUpstreamSettings`。`saveChannelUpstreamSettings:330` 是无锁 read-modify-write 整个 JSON blob，12 分钟探测窗口会放大 lost-update。

## 方案设计

### 后端

**1. 重构 `controller/channel_upstream_probe.go`（解耦预算/统计/来源/取消）**
- 新增 `probeTaker interface{ take() bool }`
- 6 个包级 `probeStat*` 收进 `type probeStatSink struct{...atomic.Int64}` + `record(v)`（nil 安全）/ `reset()`；新增 `var taskProbeStats probeStatSink`
- `resetProbeRoundBudget()` 追加 `taskProbeStats.reset()`
- 新增 `type probeRunOptions struct { scene, source string; budget probeTaker; stats *probeStatSink; ctx context.Context }`
- `probeChannelModels` 签名改为 `(channel, models, opts) map[string]probeResult`（**返回 probeResult 而非 verdict**，手动 UI 需 statusCode/duration/message）；循环内 `opts.stats.record()`、`opts.ctx` 取消检查、`recordProbeLog(..., opts.source)`
- 抽 `probeChannelUnsupportedReason(channel) string`（只做渠道级判定），`probeUnsupportedReason` 内部改调它，行为不变
- `recordProbeLog(channel, res, scene, source)`；`Other` 追加 `probe_source:%s`，`TokenName` 保持 `model-probe`
- `probeFilterPendingModels`（任务路径）改用 `probeRunOptions{source:"task", budget:newProbeBudget(), stats:&taskProbeStats}`，并把 `map[string]probeResult` 投影成 verdict 再喂 `filterByProbeVerdicts`（后者签名不变，保护 `TestFilterByProbeVerdicts`）
- 新增 `type manualBudget struct{ remaining int }` 实现 `take()`

**2. 新文件 `controller/channel_upstream_probe_manual.go`**
```go
const manualProbeMaxPerRequest = 50
const manualProbeMarkerTTL = 90 * time.Second
func manualProbeMarkerKey(channelID int) string        // "upstream_manual_probe:{id}"
func manualProbeActive(channelID int) (userID int, ok bool)   // RedisGet
func manualProbeRefresh(channelID, userID int) error          // RedisSet TTL
type probeModelResultDTO struct{ Model, MappedModel, Scene, Verdict string; StatusCode int; Duration float64; Message, SkipReason string; Approve bool }
func ProbeChannelUpstreamModels(c *gin.Context)   // POST .../upstream_updates/probe
```
handler 流程：bind{id,models} → 校验 `0<len<=50` → GetChannelById → **渠道级短路**（约束 E）→ 从 settings 算 pending 集与 sceneOf → `batch=intersect(models,pending)`、差集入 `rejected`（约束 G）→ 查/刷 Redis 标记（他人持有→拒绝；本人→刷新）→ 按 scene 分组调 `probeChannelModels(opts{source:"manual", budget:&manualBudget{len(batch)}, stats:nil, ctx:c.Request.Context()})` → 返回 `{supported, results, rejected, progress}`。**不写 settings**。

**3. `controller/channel_upstream_update.go`**
- `:396` 前插避让：`if _, ok := manualProbeActive(channel.Id); ok { allowAutoApply=false; upstreamInfo(...) }`
- `:611` 轮末统计改读 `taskProbeStats.*.Load()`

**4. `router/api-router.go:163` 后**：`channelRoute.POST("/upstream_updates/probe", controller.ProbeChannelUpstreamModels)`（`channelRoute` 已 `AdminAuth()`，`c.GetInt("id")` 可取）

### 前端（`~/code/ezlinkai-web`）

**1. 新文件 `sections/channel/tables/probe-modal.tsx`** — shadcn `Dialog`
- 打开时 `JSON.parse(channel.other_settings ?? '{}')` 取 `upstream_model_update_last_detected_models`/`..._last_removed_models`，零请求渲染候选（字段带 omitempty，容错缺失）
- 空态引导；开始前 `AlertModal` 二次确认（含「将发起 N 次真实上游请求，可能产生费用」）
- 循环：`while(queue.length && !aborted){ batch=queue.splice(0,50); r=await postProbe({id,models:batch},signal); if(!r.supported){showUnsupported;break} merge(r.results); }`
- `useRef<AbortController>`，`onClose` abort
- 结果表：model / 方向 / verdict Badge / status_code / duration / message(title 展全文) / checkbox
- **默认勾选纯函数** `shouldPreselect(verdict,scene)`（放 lib/）：add+alive→勾；remove+(not_found|unavailable)→勾；**skipped/rate_limited/inconclusive 一律不勾**
- verdict 文案中性化：`unavailable`→「上游不可服务(503)」
- 应用：勾选项按 scene 拆 `add_models`/`remove_models` 调现有 `/api/channel/upstream_updates/apply`；响应 `added_models`/`removed_models` 与提交值做差集，非空 toast 告警（约束 D-1）

**2. `sections/channel/tables/cell-action.tsx`** — View Models 下加菜单项（lucide `Radar`，文案「模型探针」）+ 挂 `<ProbeModal onApplied={onDataChange}/>`

**3. 代理路由** `app/api/channel/upstream_updates/probe/route.ts`（7 行照抄 detect）

## 影响范围
- 定时任务路径行为**完全不变**（解耦是等价重构，靠现有 `TestFilterByProbeVerdicts` + 新增回归测试保护）
- 不改 abilities 表、不改 settings 结构、无数据库迁移
- 手动探针写 `LogTypeSystem` 日志，`SumUsedQuota` 按 `LogTypeConsume` 过滤，不进营收统计

## 验证方式
- 单测（纯函数/无 DB）：预算不触碰 round budget、统计不污染 taskProbeStats、intersect 只探 pending、渠道级短路不产生 skipped 结果、`buildProbeLogOther` 的 source 标记、`shouldPreselect` 6×2 全表（skipped 两 scene 都不勾）
- `go build ./... && go vet ./...` + `go test ./controller/... ./model/...`
- 测试环境 test2.ezlinkai.com 渠道 57：点菜单→勾选→应用，核对 models 变更 + 日志页 `token_name=model-probe` 带 `probe_source:manual`
