# 对接 BFL FLUX 3 Video 模型

## 背景与目标
新增 BFL（Black Forest Labs）的 `flux-3-video` 视频生成模型。Flux 渠道已存在（`ChannelTypeFlux=46`，BaseURL 已是 `https://api.bfl.ai`，`relay/channel/flux/` 已有图像生成 `Adaptor`），因此本任务是在既有 Flux 渠道上新增 `VideoAdaptor`，而非新建渠道。

flux-3-video 为异步模式（POST 提交 → 拿 id → GET 轮询到 `Ready`），与 `relay/channel/luma/video_adaptor.go` 同构。认证用 `x-key` header；轮询用 `https://api.bfl.ai/v1/get_result?id=<id>` 重构（沿用现有图像 adaptor 做法）。

已确认决策：单一模型名 `flux-3-video`，`mode`（t2v/i2v/v2v/draft_enhance）由请求体透传；初版支持全部 4 种模式；按秒计费（USD），HD=$0.17/s。

## 方案设计（已实施）
1. **新建 `relay/channel/flux/video_model.go`**：`FluxVideoRequest`（mode/prompt/keyframes/start_video/draft_cache/resolution/duration/aspect_ratio/generate_audio/safety_tolerance/draft/version）、`FluxVideoSubmitResponse`（id/polling_url）、`FluxVideoPollingResponse`（status/result.sample）。keyframes 用 `json.RawMessage` 透传，duration 用 `interface{}` 兼容整数秒/"auto"。
2. **新建 `relay/channel/flux/video_adaptor.go`**：实现 `channel.VideoAdaptor`。`HandleVideoRequest` 提交并算 quota；`HandleVideoResult` 轮询映射 `Ready→succeed / Error·Moderated→failed / 其余→processing`。provider=`flux`。
3. **`relay/channel/video_helper.go`**：新增 `XKeyAuthHeaders`。
4. **`relay/helper/main.go`**：`GetVideoAdaptor` 加 `flux-3-video` 前缀 case；`GetVideoAdaptorByProvider` 加 `"flux"` case。
5. **`common/video-pricing.go`**：`DefaultVideoPricingRules` 加 flux-3-video（hd=0.17、fhd=0.34⚠️占位、兜底 0.17，per_second USD）。
6. **`common/model-ratio.go`**：`DefaultModelPrice` 加 `"flux-3-video": 0.85` 兜底。

## 影响范围
- 不影响 flux 图像生成（`flux-3-video` 前缀与图像 `flux-`/`flux.` 分发链路独立）。
- 无数据库 schema 变更（复用 `Video` 表 Mode/Duration/Resolution/Sound/Prompt 字段）。

## 待核对/后续
- ⚠️ **FHD 单价 $0.34/s 为占位估算，draft 折扣未知**——上线前需去 bfl.ai/pricing 计算器逐档核对。
- 初版直接透传 BFL 签名 mp4 URL（同 luma）；如需防签名过期可后续接 `relaychannel.UploadVideoURLToR2`。

## 验证方式
1. `go build ./... && go vet ./...` —— 已通过。
2. 后台 Flux 渠道 models 加 `flux-3-video`、填 BFL key。
3. t2v/i2v/v2v 分别提交 → 轮询至 succeed，核对 `videos` 落库与 `logs` 扣费（$0.17/s×时长）。
